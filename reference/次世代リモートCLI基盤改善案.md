

### 次世代リモートCLI基盤（Dynamic Manifest & Non-blocking UX）移行指示プロンプト

あなたは**GoおよびTypeScriptに精通したシニアシステムアーキテクト**として、現在の「ハードコードされたホワイトリスト制」を廃止し、セキュアで動的な「拡張マニフェスト駆動型アーキテクチャ」へのアップグレードを完遂してください。

#### 1. 実行モードと停止ポイント
- **実行モード**: 提案に留まらず、プロトコル定義からGoハンドラ、プラグインUIのロジックまで実装してください。
- **停止ポイント（確認必須）**:
  1. `capabilities.json` のスキーマと JSON-RPC の新メソッド定義完了時。
  2. サーバー起動時の SHA-256 ハッシュ検証ロジックの実装完了時。
  3. モバイル端末での「非ブロッキング競合解決」のフロー図提示時。

#### 2. 目的
個別コマンド（gemini, git等）のハードコードを排除し、マニフェストファイルで権限と機能を定義できる汎用基盤を構築する。また、モバイル環境（iPhone）での再接続時に、大量のログ受信とファイル同期の競合がUIをフリーズさせない仕組みを実現する [1, 3]。

#### 3. 技術仕様

- **動的マニフェスト駆動 RPC (`extension.invoke`)**:
    - 個別のメソッド（`cli.exec` 等）を `extension.invoke` という抽象メソッドへ統合する [1]。
    - 実行許可、コマンドパス、引数のバリデーションルールを外部の `capabilities.json` または `permissions.yml` で管理する。
    - サーバー接続時のハンドシェイクで、現在許可されている機能の JSON Schema をクライアントに送信し、プラグイン側で動的にコマンドを生成可能にする。

- **SHA-256 による実行整合性検証**:
    - マニフェストに記載されたバイナリの SHA-256 ハッシュを実行直前に検証し、悪意ある改変や予期せぬ更新を防止する。
    - （将来的な読み取り専用パーティション配置を考慮したパス設計にする [1]。）

- **モバイル向け非ブロッキング競合解決**:
    - 再接続時、大量のバックログ（JSONLログ）を受信している間は、ファイルの競合解決（3-way merge等）をバックグラウンドにスタッシュし、UIをロックしない [1]。
    - **優先順位制御**: CLIストリームの表示を最優先し、ストリームが終了または安定したタイミングで「未解決の競合があります」という視覚的通知を出し、ユーザーをマージUIへ誘導する。

- **ログ保持と自動クリーンアップ**:
    - JSONLログは「プロセス終了から24時間」または「1プロセスあたり50MB」のいずれかに達した時点で自動削除するロジックを Go デーモンに実装する [2]。
    - デーモン起動時に `~/.gemini-cli/logs/` 配下の期限切れファイルを一掃する。

#### 4. 安全性・論理ルール
- **パス検証の継承**: 既存の `validateWorkingDir`（`EvalSymlinks` + `filepath.Rel`）による Vault 外へのエスケープチェックを、すべての `extension.invoke` に適用すること [4, 5]。
- **プロトコルの優先順位**: 通信効率化のため `cli.output.batch` を標準とし、単発の `cli.output` はレガシーサポートとする [6]。
- **モバイルUX**: 「自動再開（Auto-resume）」はデフォルトONとし、ユーザー設定で変更可能にする [2]。

#### 5. 完了条件 (DoD)
- [ ] `extension.invoke` 経由で、マニフェストに定義された任意のツール（Gemini等）が実行できる。
- [ ] ハッシュ値が一致しないバイナリの実行が拒否され、エラーログが記録される。
- [ ] iPhone 端末で、大量のログ出力中の再接続が発生してもエディタの操作が維持され、ログ受信後に競合解決の通知が正しく表示される。
- [ ] 24時間を経過した古いログファイルが、デーモン起動時または定期実行でクリーンアップされる。

#### 6. ブランチ運用指針（next 統合 → upstream 還元）

- `next` を統合開発ブランチとして実装を進める。
- upstream に還元可能な変更は、後段で `feat/cli-core` 系へ cherry-pick して PR 化する。
- Gemini 専用 UX / iOS 配布運用など、上流非依存の変更は `feat/gemini-ui` / `feat/ios-enhancements` 側へ分離する。

| 改善項目 | 実装先 (現在) | 還元候補ブランチ | 備考 |
|---|---|---|---|
| `extension.schema` / `extension.invoke` プロトコル追加 | `next` | `feat/cli-core` | 汎用RPC拡張として還元対象 |
| capabilities manifest / schema | `next` | `feat/cli-core` | 実行ポリシー外部化 |
| 起動時 SHA-256 検証 | `next` | `feat/cli-core` | セキュリティ強化 |
| JSONL 24h / 50MB cleanup | `next` | `feat/cli-core` | デーモン運用ロジック |
| 非ブロッキング競合解決（stream優先） | `next` | `feat/gemini-ui` 先行、必要に応じて `feat/cli-core` 再検討 | UI/UX依存が強いため段階切り出し |
| Auto-resume 設定（デフォルト ON） | `next` | `feat/gemini-ui` | ユーザー体験設定 |
