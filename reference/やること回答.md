### 1. 再接続復旧のプロダクト方針を確定する
- **自動再開をデフォルトONにするか、確認ダイアログを挟むか**

**おすすめ（iPhoneモバイル重視）**:
- **デフォルトON + 設定でOFF可能**にする。
- 理由：モバイルはネットワークが不安定（Wi-Fi→モバイルデータ切り替え、画面ロックなど）なので、**シームレス復旧が最大の価値**。
- 初回は「接続が切断されました。再開しますか？」のようなトースト通知＋「今後表示しない」チェックボックスを出す。
- 設定項目：`Settings > Gemini CLI > Auto Resume on Reconnect`（デフォルト: ON）

### 2. ログ保持ポリシーを確定する
- JSONLログの保持時間、最大サイズ、削除トリガー

**おすすめ設定**:
- **最大サイズ**: 10MB 〜 50MB（1プロセスあたり）
- **保持期間**: プロセス終了後 **24時間**（または Vault 設定の "Keep CLI logs for" でユーザー指定）
- **削除トリガー**:
  - プロセス終了 + 24時間経過
  - サーバー起動時に古いログを自動掃除
  - 手動コマンド `gemini cleanup-logs` 追加
- 保存場所: `~/.gemini-cli/logs/` か Vault 内の `.gemini/logs/`（後者の方が Obsidian から見やすい）

### 3. cli.output と cli.output.batch の公開契約を確定する
- 両方維持か、段階的移行か、クライアント側優先ルール

**おすすめ**:
- **両方維持**（後方互換重視）
- **クライアント側優先ルール**: 
  - 新しいクライアント（CliTerminalView）は `cli.output.batch` を優先して購読
  - 古いクライアントやシンプルな `cli.exec` は従来の `cli.output` を受け取る
- `proto/README.md` に明確に「**batch は推奨**、単発 output はレガシーサポート」と記載

### 4. mobile/dist の運用方針を確定する
- Git管理するか、CI/リリース時生成に寄せるか

**おすすめ**: **CI/リリース時に生成**（Git 管理はしない）
- `mobile/dist` はビルド成果物なので `.gitignore` に入れる
- GitHub Actions で `mobile` をビルドして artifact 化
- 理由：ファイルが重くなりやすい + 常に最新ビルドを保証できる
